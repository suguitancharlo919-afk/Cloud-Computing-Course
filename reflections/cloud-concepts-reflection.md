## Identifying the Models

**Google Drive** is a **SaaS (Software as a Service)** because I'm using the application through my browser or phone app — I don't manage any server or infrastructure behind it. Its deployment model is **Public Cloud**, since Google owns and manages the infrastructure and shares it across millions of users like me.


**GCash** is also **SaaS**, It use an app/interface to send money or pay bills, with all the backend processing hidden from me. I'd classify its deployment model as **Private Cloud**, since it handles sensitive financial data and is restricted to GCash's own controlled infrastructure rather than being shared openly like a typical public app.

**Netflix** is another **SaaS** example — A streaming content, I don't manage servers or software updates. Its deployment model is **Public Cloud** as well, since it runs on shared cloud infrastructure (like AWS) serving subscribers worldwide.
## Git & GitHub for Cloud Projects

Version control matters a lot when working with cloud infrastructure because cloud setups are usually collaborative, and one wrong config change can break something for everyone, not just for you. Git lets me track every change made to code or configuration files, so if something goes wrong, I can just roll back to a previous working version instead of panicking.

GitHub makes teamwork easier through features like pull requests, branches, and commit history. Instead of overwriting each other's work, my teammates and I can work on separate branches, review each other's changes before merging, and leave comments to explain why something was changed. This prevents errors, keeps everyone accountable, and makes managing cloud resources way more organized and less stressful.
